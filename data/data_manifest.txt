================================================================================
DATA MANIFEST — NASA C-MAPSS Turbofan Engine Degradation Simulation Data Set
================================================================================
Raw data is NOT committed to git (data/raw/ is gitignored). This file is the
contract that lets anyone reproduce the exact same data/raw/ folder.
All numbers below were VERIFIED on the downloaded files on 2026-11-01.

--------------------------------------------------------------------------------
SOURCE
--------------------------------------------------------------------------------
Original publisher : NASA Ames Prognostics Center of Excellence (PCoE),
                     "Turbofan Engine Degradation Simulation Data Set"
Download used      : Kaggle dataset "behrad3d/nasa-cmaps" (version 1) via kagglehub
Reference paper    : A. Saxena, K. Goebel, D. Simon, N. Eklund, "Damage Propagation
                     Modeling for Aircraft Engine Run-to-Failure Simulation",
                     Proc. 1st Int. Conf. on Prognostics and Health Management
                     (PHM08), Denver CO, 2008. DOI: 10.1109/PHM.2008.4711414

--------------------------------------------------------------------------------
HOW TO REPRODUCE data/raw/
--------------------------------------------------------------------------------
1. Activate the project venv (Python 3.12) with requirements.txt installed.
2. Download (a free Kaggle login may be requested the first time):
     python -c "import kagglehub; print(kagglehub.dataset_download('behrad3d/nasa-cmaps'))"
   It prints a cache folder. The files are inside a NESTED  CMaps/  subfolder.
3. Copy these 13 files from <printed folder>/CMaps/ into data/raw/:
     train_FD001..4.txt, test_FD001..4.txt, RUL_FD001..4.txt, readme.txt
   Do NOT copy:
     x.txt                               - 218 unexplained numbers, not part of
                                           NASA's dataset, matches no RUL file
     Damage Propagation Modeling.pdf     - the reference paper (copyrighted;
                                           good reading, but not data)
4. Verify with the SHA-256 checksums below (Git Bash: cd data/raw && sha256sum -c ../sha256sums.txt)
   and the expected shapes table.

--------------------------------------------------------------------------------
FILE FORMAT  (the gotchas)
--------------------------------------------------------------------------------
- Plain text, whitespace separated, NO header row, TRAILING SPACES on each line.
  Read with:  pd.read_csv(path, sep=r"\s+", header=None, names=COLUMNS)
  Using sep=" " gives 28 columns (2 extra all-NaN columns) - verified.
- 26 columns:
     1  unit_id      engine number within that file
     2  cycle        operating cycle, starts at 1
     3-5  op1..op3   operational settings (altitude / Mach / throttle-type inputs)
     6-26 s1..s21    21 sensor measurements
  (readme.txt says "sensor measurement 26" - that is a typo in NASA's readme;
   there are 21 sensors.)
- readme.txt is not UTF-8: open it with encoding="latin-1".
- RUL_FD00X.txt: one integer per TEST engine (in unit_id order) = the true number
  of remaining cycles AFTER the last cycle present in test_FD00X.txt.

--------------------------------------------------------------------------------
SEMANTICS
--------------------------------------------------------------------------------
- TRAIN engines run from healthy until FAILURE  ->  RUL label for each row is
  computed as  max_cycle(unit) - cycle  (last row of each engine has RUL = 0).
- TEST engines are CUT OFF some time before failure. Their RUL is known ONLY at
  the last observed cycle (from RUL_FD00X.txt). Test RUL must never be computed
  from max(cycle) - those engines did not fail.

--------------------------------------------------------------------------------
PROJECT USAGE
--------------------------------------------------------------------------------
- FD001 : primary benchmark - all models trained and compared here.
- FD002 : drift demo - an FD001-trained model sees 6 operating conditions
          (covariate shift), detected with KS/PSI, then retraining is triggered.
- FD003/FD004 : optional extensions.
