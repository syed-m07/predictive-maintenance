DEVIATIONS & SHORTCUTS LOG
==========================
Rule (set by the owner, 2026-11-01): NO shortcuts. The project keeps its original,
resume-grade scope regardless of the deadline. Any shortcut or deviation from the
original plan must be (1) proposed to the owner FIRST, (2) approved, and (3) logged
here with the reason. Nothing in this file may be applied silently.

Format:
  [ID] date | status (PROPOSED / APPROVED / REJECTED / REVERTED)
  What: ...
  Original plan: ...
  Why: ...
  Impact on results / story: ...

Note: fixes for things that were WRONG in the original plan (e.g. per-engine
normalisation, the 17731 row count) are corrections, not shortcuts. They are
documented in docs/DECISIONS.md, not here.

[DV-002] 2026-11-02 | APPROVED
What: Final (tuned) models are trained on the same 80 training engines, with the
  same 20 validation engines for early stopping, as every other model. They are
  NOT retrained on all 100 engines.
Original plan: planner task w4t5, "Retrain on full training data with best params".
Why: every model family (XGBoost, TCN, Bi-LSTM, uni-LSTM, ROCKET) then follows
  one identical protocol, so the comparison table is strictly like-for-like.
  The final model also keeps a held-out early-stopping signal instead of a
  guessed fixed tree/epoch count.
Impact: final models see 80% of the training engines. Absolute test scores may
  be slightly worse than an all-100 refit would give; the model comparison is
  fairer. Applies to all model families.

[DV-003] 2026-11-02 | APPROVED
What: ROCKET's ridge-penalty grid is np.logspace(-3, 6, 10) instead of the
  planner's np.logspace(-3, 3, 10). The penalty is chosen on the 20 validation
  engines (DECISIONS K2), not by RidgeCV's leave-one-out.
Original plan: planner w7t3 / HANDOFF: "RidgeCV(alphas=np.logspace(-3,3,10))".
Why: measured on FD001 with 10,000 kernels: validation RMSE fell at every
  step up to the largest planner value (alpha 1e-3: 20.80 ... alpha 1e3: 18.91),
  so the best alpha lay outside the grid. Keeping the grid would under-rate ROCKET.
  Rule agreed with the owner: if the best alpha is still on the new edge, stop and
  report instead of widening again.
Impact: ROCKET is evaluated at a properly chosen penalty. Same number of grid
  points; ridge time is unchanged.

--------------------------------------------------------------------------------
[DV-004] 2026-11-02 | APPROVED
What: The drift demo's no-drift control is FD001 training engines (reference)
  vs FD001 VALIDATION engines. FD001 validation vs FD001 TEST is kept and
  reported as a separate "harmless shift" case, not as the control.
Original plan: HANDOFF section 12, "run FD001-val vs FD001-test as a no-drift
  control" (it must not alarm).
Why: measured, that pair DOES alarm (KS 14/14 sensors, PSI > 0.2 on 13,
  median PSI 0.27). The test engines were cut off before failure, so their
  readings are mostly healthy early-life ones, while validation engines run to
  failure. Shown by the script: cutting the validation engines off the same way
  reproduces the shift against the reference (alarm in 14/20 draws) and then
  matches the test engines (0/20 alarms, median PSI 0.017). Training vs
  validation engines (same population, full lifetimes) gives PSI > 0.2 on
  0 sensors -> a real control.
  Also approved with it: the per-sensor rule needs KS p<0.05 AND PSI>0.2
  (alarm at >= 3 sensors). This fits the planned flag_drift(ks_alpha,
  psi_threshold, min_features=3) signature; KS alone flags 5/14 sensors on the
  control because of the large, autocorrelated samples.
Impact: the control passes for the right reason. The FD001-test case becomes
  an extra finding: an alarm is not the same as harm (the FD001 models score
  their usual 14-18 RMSE on that batch), so alarms need interpreting.
